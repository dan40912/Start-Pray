# PRD-008 — 多語系完成度 (Internationalization Completeness)

- 階段：**P2**
- 狀態：未開始
- 依賴：無;但 PRD-003/004/005 新增的文案都應走 i18n,做完本 PRD 後它們更好補。
- 對應落差：叫 Global Prayer Room,但目前實質只有中文 + 部分英文路由。

---

## 1. 目標 (Goal)

把多語系從「部分英文頁」推進到「完整、可擴充、CI 會擋漏字」:
補完 `en` 文案、建立新增 locale 的標準流程、讓 `check-i18n` 在缺 key 時讓 CI 失敗。

## 2. 背景與現況 (Background)

- i18n 核心:`src/lib/i18n/index.js`,locale 檔 `src/lib/i18n/locales/zh-TW.js`、`en.js`。
- 英文路由樹已存在:`src/app/en/*`(about、prayfor、overcomer、login、signup、terms、global-prayer-room、howto、customer-portal、forgot-password)。
- 檢查腳本:`scripts/check-i18n.cjs`,npm script `npm run i18n:check`。
- **現況**:en locale 可能缺 key / 與 zh-TW 不對齊;新增第三語言沒有標準流程;CI 是否強制 i18n 檢查未知。

## 3. 範圍 (Scope)

**In scope**
- 對齊 `en.js` 與 `zh-TW.js` 的 key 集合(補齊缺漏,移除孤兒 key)。
- 強化 `check-i18n.cjs`:列出「某 locale 有、另一 locale 缺」的 key,缺 key 時 exit code ≠ 0。
- 文件化「新增一個 locale」的步驟(寫進 `docs/i18n.md`,若存在則更新)。
- 確保語言切換在 `site-chrome.js` 可用且保留當前頁。

**Out of scope(不要做)**
- ❌ 不實際翻譯成第三語言(只建機制)。
- ❌ 不接機器翻譯 API。
- ❌ 不改網址結構策略(維持 `/en` 前綴現狀)。

## 4. 詳細實作步驟 (Implementation)

**Step 0 — 差異盤點(先做,先回報)**
跑 `npm run i18n:check`,並用腳本/grep 列出 zh-TW 與 en 的 key 差集,貼進回報。

**Step 1 — 對齊 key**
- 以 zh-TW 為**權威 key 集合**(它是主語言)。
- `en.js` 補齊所有缺的 key(英文翻譯;不確定的措辭標 `// TODO: review wording` 但**必須有英文值**,不可留空或中文)。
- 移除 en 有、zh-TW 沒有的孤兒 key(或反向補進 zh-TW,依該 key 是否仍被使用 —— grep 確認後決定,並在回報說明)。

**Step 2 — 強化檢查腳本**
`scripts/check-i18n.cjs`:
- 載入所有 locale,計算相對 zh-TW 的 missing / extra key。
- 有 missing 時 `process.exit(1)` 並印出清單;全綠時印出 OK。
- 巢狀 key 要遞迴比對(若 locale 是巢狀物件)。

**Step 3 — CI 串接**
- 在 `.github`(workflow)或 lint 流程加入 `npm run i18n:check`(看現有 CI 結構;若無 CI,改在 `package.json` 的 build 前置或 README 註明手動跑)。在回報說明你接在哪。

**Step 4 — 新增 locale 流程文件**
- `docs/i18n.md`:用條列寫「複製 zh-TW.js → 翻譯 → 在 index.js 註冊 → 建 `/xx` 路由(如採前綴策略)→ 跑 i18n:check」。

## 5. 資料模型變更

- **無**。純前端 / 腳本 / 文件。

## 6. 驗收標準 (Acceptance Criteria)

1. Key-diff 盤點(Step 0)列在回報中。
2. `en.js` 與 `zh-TW.js` 的 key 集合完全一致(no missing, no orphan);所有 en 值為英文且非空。
3. `npm run i18n:check` exits 0 when locales are aligned, and exits non-zero (with a printed list) if a key is removed from one locale — demonstrate by temporarily deleting a key.
4. Nested keys are compared recursively (if applicable).
5. 切換語言(`site-chrome.js` 切換器)會切到對應 locale 並停在同一頁(或對應 `/en` 頁)。
6. `/en` 下主要頁(about, prayfor, overcomer, login, signup, terms, global-prayer-room, howto)無未翻譯的殘留中文硬字串(抽查首屏)。
7. `docs/i18n.md` 含「新增 locale」步驟。
8. i18n 檢查已接進 CI 或建置前置(回報指出位置)。
9. `npm run lint` + `npm run build` pass.
10. No backend / schema changes (`git diff` 僅含 locale 檔、check 腳本、CI 設定、i18n 文件、必要的 switcher 元件)。

## 7. 給 Codex 的防錯提醒 (Guardrails)

- ✅ zh-TW 是權威主語言;對齊以它為準。
- ❌ en 值不可留空、不可塞中文佔位;不確定就給合理英文 + `// TODO`。
- ❌ 不接機翻 API、不 `npm install` i18n 框架(沿用現有自製 i18n)。
- ⚠️ 移除「孤兒 key」前先 grep 確認真的沒被引用,否則可能弄壞頁面。
- ✅ 改 `check-i18n.cjs` 後親自跑一次證明它真的會在缺 key 時 fail。
