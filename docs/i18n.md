# Internationalization

Start Pray keeps the existing Chinese routes as the default public experience and adds English pages under `/en`.

The goal is a small, reversible i18n layer that does not disturb prayer privacy, response permissions, media upload rules, or the current customer/admin flows.

## Route Strategy

- Default locale: `zh-TW`
- English locale: `en`
- English public pages live under `/en`, for example `/en/prayfor` and `/en/global-prayer-room`.
- Existing Chinese URLs stay unchanged.
- Member pages under `/en/customer-portal` currently redirect to the existing Chinese member center until the private dashboard is translated.

## Dictionary Files

Locale text lives in:

```text
src/lib/i18n/locales/zh-TW.js
src/lib/i18n/locales/en.js
```

Shared helpers live in:

```text
src/lib/i18n/index.js
```

Use `getDictionary(locale)` for UI text, `localizePath(path, locale)` for links, and `normalizeLocale(locale)` when accepting a prop from a route wrapper.

## What Should Be Translated

Translate stable product UI:

- Navigation and footer labels
- Page headings and helper text
- Form labels, placeholders, hints, and error messages
- Empty states and loading states
- Public metadata and structured data
- Button labels and accessible labels

Do not translate user-generated content automatically:

- Prayer card titles and descriptions
- Prayer responses
- Uploaded media labels or filenames
- Location names stored by users

Database category names may still appear in Chinese until category localization is added at the data/model layer.

## Privacy Rules

Do not let i18n changes bypass privacy filtering.

Private `HomePrayerCard` data must not leak on public pages or APIs:

- title
- description
- image
- owner
- detailsHref

The Global Prayer Room may show anonymous approximate prayer lights, but private card details must stay hidden in every locale.

## SEO

English pages should use localized metadata and alternate links. Keep legacy pages and account flows out of public indexing where they are already disallowed.

When adding a new public route, update:

```text
src/app/sitemap.js
src/app/robots.js
src/lib/seo.js
```

## Checks

Run this before committing i18n changes:

```bash
npm run i18n:check
npm run lint
npm run build
```

`npm run i18n:check` compares the Chinese and English dictionaries so missing keys or mismatched array lengths fail early.

## Known Gaps

- Public user-generated prayer content remains in its original language.
- Category labels come from existing data and may still be Chinese on English pages.
- Customer portal, admin, and some long-form informational pages are route-compatible but not fully translated yet.
